# springboot-java-backend

The same REST contract as the service in the parent directory, built on Spring Boot 4 the way most Java shops build it. It exists so the cost and the benefit of a framework can be measured rather than argued about — see [ADR-0005](../docs/adr/0005-spring-boot-port.md).

Both services answer the same `openapi.yaml`, and CI runs the same `scripts/smoke.sh` against both images on every change.

## Quick start

```sh
./gradlew build          # compile and test
./gradlew bootRun        # http://localhost:8080
```

Or from a container:

```sh
docker build -t spring-task-service .
docker run --rm -p 8080:8080 --read-only --tmpfs /tmp spring-task-service
../scripts/smoke.sh http://localhost:8080
```

The same curl sequence as the parent README works unchanged:

```sh
curl -isS -X POST localhost:8080/v1/tasks \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: "order-42"' \
  -d '{"title":"write docs"}'

curl -sS localhost:8080/v1/tasks?limit=20
curl -sS -X POST localhost:8080/v1/cubes -H 'Content-Type: application/json' -d '{}'
```

## Endpoints

| Method | Path | Scope | Notes |
|---|---|---|---|
| GET | `/v1/tasks` | `tasks:read` | `?limit` (1–100, default 20), `?cursor`; unknown parameters are a 400 |
| POST | `/v1/tasks` | `tasks:write` | 201 with `Location` and `ETag`; honours `Idempotency-Key` |
| GET | `/v1/tasks/{id}` | `tasks:read` | `If-None-Match` gives a 304 |
| PUT | `/v1/tasks/{id}` | `tasks:write` | `If-Match` required: 428 without it, 412 if stale |
| DELETE | `/v1/tasks/{id}` | `tasks:write` | 204, `If-Match` required |
| GET/POST | `/v1/cubes` | `cubes:read` / `cubes:write` | `{}` is a valid body; every field has a contract default |
| GET/PUT/DELETE | `/v1/cubes/{id}` | `cubes:read` / `cubes:write` | as for tasks |
| GET | `/v1/cubes/{id}/pdf` | `cubes:read` | `application/pdf`, generated byte by byte |
| GET | `/v1/nautical-flags` | `flags:read` | `text/event-stream`, `?text` (1–256 characters from A–Z, a–z, 0–9 and space) as one signal flag per event, `{"char":"a","flag":"Alfa","glyph":"⬜🟦"}`; `?intervalMs` (default 1000, 50–60000) |
| GET | `/health/live`, `/health/ready` | public | `{"status":"UP"}` |
| GET | `/metrics` | public | Prometheus text format |
| GET | `/openapi.yaml` | public | the contract |

Scopes are prefixed with `APP_AUTH_SCOPE_PREFIX`, default `task-service:`, so a full scope reads `task-service:tasks:read`.

Actuator serves the canonical equivalents at `/actuator/health/liveness`, `/actuator/health/readiness` and `/actuator/prometheus`. The paths above are kept because the deployment manifest, the ingress rule that restricts `/metrics` and the smoke script are written against them.

## Configuration

Every `APP_*` variable from the parent README works here unchanged, through Spring's relaxed binding: `APP_MAX_BODY_BYTES` binds to `app.max-body-bytes`, `APP_AUTH_JWKS_URL` to `app.auth.jwks-url`. Defaults and ranges are identical, and an out-of-range value still fails at startup with **exit code 2**.

Authentication is off until `APP_AUTH_ISSUER` is set and on the moment it is. Setting `APP_AUTH_ENABLED=true` without the rest is a startup failure, not a silent bypass. With authentication off the service logs `auth.disabled` at WARN on every boot.

The nautical-flag stream adds its own, Spring-only variables: `APP_NAUTICAL_FLAGS_DEFAULT_INTERVAL_MILLIS` (1000), `APP_NAUTICAL_FLAGS_MIN_INTERVAL_MILLIS` (50), `APP_NAUTICAL_FLAGS_MAX_INTERVAL_MILLIS` (60000) and `APP_NAUTICAL_FLAGS_MAX_TEXT_LENGTH` (256) bound what a caller may ask for; `APP_NAUTICAL_FLAGS_MAX_DURATION_SECONDS` (300) and `APP_NAUTICAL_FLAGS_MAX_CONCURRENT_STREAMS` (100) bound what a stream costs. A default outside its own bounds is a startup failure like any other.

A few variables now map onto Spring's own properties rather than being read directly: `APP_HOST` and `APP_PORT` drive `server.address` and `server.port`, `APP_SHUTDOWN_GRACE_SECONDS` drives `spring.lifecycle.timeout-per-shutdown-phase`, and `APP_LOG_LEVEL` drives `logging.level.root` (`WARNING` is accepted as well as Logback's `WARN`).

## Where this differs from the zero-dependency service

Every difference below was a choice to take Spring's default rather than to reproduce the original exactly. They are listed because a port that loses behaviour quietly is worse than one that loses it loudly.

| | Zero-dependency | Spring Boot |
|---|---|---|
| Request metrics | `http_server_requests_total{method,route,status}` | `http_server_requests_seconds_*{method,uri,status,outcome}` |
| Latency histogram | `http_server_request_duration_seconds_bucket` | `http_server_requests_seconds_bucket` |
| In-flight gauge | `http_server_requests_in_flight` | `http_server_requests_seconds_active_count` |
| Heap metrics | `jvm_memory_heap_used_bytes` | `jvm_memory_used_bytes{area="heap"}` |
| `Cache-Control` | `no-store` | `no-cache, no-store, max-age=0, must-revalidate`, plus `Pragma` and `Expires` |
| Body validation | every violation in one 422 | every *range* violation in one 422; the **first** structural error (unknown field, wrong type) per round trip |
| Log fields | `ts`, `event`, `logger` | `@timestamp`, `message`, `logger_name` |
| Access log `bytes` | exact | `-1` where no `Content-Length` was set |
| Malformed request line | RFC 9457 problem document | Tomcat's plain HTML 400 |
| Oversized header | RFC 9457 problem document | Tomcat's plain HTML 400 |
| `/v1/nautical-flags` | in the shared contract, not yet served (404) | served |
| Access log for a stream | — | written when the stream starts; `durationMs` is the handler's time, not the stream's |

Dashboards and alerts written against the sibling service do not carry over. What does carry over is that metric labels are route templates, so `/v1/tasks/{id}` never becomes one label per identifier; a test asserts no identifier can appear in one.

Everything else in the contract is identical, and `scripts/smoke.sh` checks 34 of those behaviours against both implementations on every build.

## What it cost

Measured, not estimated. Lines are non-blank, non-comment.

| | Zero-dependency | Spring Boot |
|---|---|---|
| Main source | 3,889 lines | 2,925 lines |
| … of which is the shared domain | 674 | 674, byte-identical |
| … so framework-facing code | ~3,100 lines | ~2,140 lines |
| Tests | 107 | 93 |
| Test source | 1,905 lines | 1,569 lines |
| Direct dependencies | 0 | 6 starters, plus `reactor-core` |
| Resolved artifacts | 0 | 83 |
| Image | 68.5 MB | 191 MB |
| Startup | ~60 ms | ~1.9 s with an AOT cache, ~4.2 s without |
| Build tooling | `javac`, `jar`, `jlink` | Gradle 9.7 and its plugins |

The framework removes about a third of the code. It does not remove as much as it looks like it should, because the pieces it replaces — routing, JSON, metrics, JWT verification — are replaced by *configuration* of those pieces, and configuring something strictly is not much shorter than writing the strict version.

What it clearly does remove is the obligation to have got them right.

## What still had to be written by hand

These are the parts where the framework had no answer, and each is the kind of control that disappears quietly if nobody is looking for it.

- **A request body size cap.** Tomcat's `maxPostSize` covers form-encoded content and the multipart limit covers multipart; neither covers a raw `application/json` body, which is the only kind this service accepts. Without `BodyLimitFilter` the only bound on a POST is available memory.
- **Refusing JWKS redirects.** A key-set URL that redirects is an SSRF primitive: the service fetches whatever it is pointed at and then trusts the keys it finds. Nimbus's default retriever follows redirects with no way to stop it.
- **A token size cap.** `NimbusJwtDecoder` has none, so without a `BearerTokenResolver` that imposes one a caller can hand over a megabyte of base64 and have it decoded.
- **503 rather than 401 when signing keys cannot be fetched.** Spring's bearer filter rethrows the failure by default, so the request merely ends up unauthenticated and the caller is told its credentials are missing — wrong, and unactionable: it would go and fetch a new token, adding load to an identity provider that is already failing.
- **Naming the required scope in a 403.** Spring's `AccessDeniedHandler` is told access was denied but not what would have been required.
- **A gauge of cached signing keys.** Without it, a provider that starts serving an empty key set looks fine until every token fails.
- **Rejecting unknown query parameters.** Spring ignores them, which turns `?limt=100` into a default page size that looks like a server bug rather than a client error.
- **The drain delay before shutdown.** Boot reports not-ready and finishes in-flight requests, but does not wait for the load balancer to notice.

## Design notes

**Conditional requests stay in the controller.** `ShallowEtagHeaderFilter` derives a tag by hashing the buffered response body, which would replace the version-derived tag, and does nothing for `If-Match`. An interceptor runs before the handler, so it could only enforce a precondition by reading the entity first — doubling the read and opening a window before the write. Passing a `LongPredicate` into the repository's compare-and-set is what closes it.

**Load shedding is a `Semaphore`.** Not a rate limiter: this service deliberately does not limit per client. It matters more here than in the sibling, because with virtual threads enabled Tomcat's `maxThreads` no longer bounds concurrency, so it is the only backpressure left.

**Request ids are an MDC filter, not Micrometer Tracing.** The service only reads `traceparent` so log lines can be correlated; spans would need a tracer bridge, an exporter and a collector. The upgrade path is `micrometer-tracing-bridge-otel` and deleting the parser.

**The domain carries no annotations.** It is instantiated in `config/DomainConfiguration`, so the files stay byte-identical to the originals and CI checks that they are.

**The nautical-flag stream is a `Flux` returned from an MVC controller.** Spring MVC subscribes to it and writes each element as a server-sent event, so `reactor-core` is the only addition — WebFlux, and the rewrite of every filter and the security chain it would mean, is not needed. A stream outlives the request that opened it, which undoes three bounds the rest of the service relies on: `LoadSheddingFilter` releases its permit as soon as the handler returns, Tomcat's 30-second async timeout would cut the stream (so `spring.mvc.async.request-timeout` is off), and graceful shutdown would wait out its grace period. `NauticalFlagStream` puts each back: its own cap on open streams (503 beyond it), a maximum duration, and completing every stream when the web server begins its graceful shutdown — after the drain delay, so clients are not cut off while the load balancer still routes here.

**`anyRequest().denyAll()`** is the runtime stand-in for the sibling's compile-time rule that every route must declare an access level. It is weaker — a forgotten route is a 403 at runtime rather than a build failure — but it fails closed.

**Jackson needed tightening in four places**, each of which otherwise turns a client mistake into a response that looks successful: unknown fields were ignored, duplicate keys took the last value, case-insensitive matching accepted `Title` for `title`, and `1.5` was truncated to `1` for an integer field.

## Testing

JUnit 5, 97 tests, no mocking framework. The service tests are the sibling's, with only the import block changed. The HTTP tests drive a real server on an ephemeral port with the JDK's own `HttpClient` rather than `TestRestTemplate`, so nothing in the test stack can smooth over a header or a status code. The JWT tests mint real tokens with real keys, including the `alg:none` and HS256-key-confusion attacks — Nimbus refuses both without configuration, and the tests are kept anyway so a change that quietly re-admitted them would not go unnoticed.

One case is not covered: failing closed once cached keys are older than `APP_AUTH_JWKS_MAX_STALE_SECONDS`, whose floor is 60 seconds. The sibling drives that with an injectable clock; Nimbus's cache takes none, so asserting it would cost a minute of wall time in every build.
